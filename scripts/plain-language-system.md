# The Plainsight Plain-Language System

The "make it easier to understand" rules, written down so every episode
gets simplified the same way instead of depending on mood.

Run every draft through these six passes in order.

---

## Pass 1 — Kill the jargon, or pay for it immediately

A technical term is allowed **only** if you define it in the same breath,
in words a twelve-year-old would use.

| Don't write | Write |
|---|---|
| intermodal freight transport | putting the same box on a ship, a truck, and a train |
| break-bulk cargo | loading a ship by hand, item by item |
| standardisation | everyone agreeing on one size |
| TEU | *twenty-foot equivalent unit* — the industry counts in twenty-foot boxes |
| containerisation | the switch to the box |
| economies of scale | the bigger it gets, the cheaper each one is |

Note what the episode script does with **TEU**: it doesn't avoid the term,
it *earns* it. Explain first, name second. Name-then-explain loses people
in the gap.

## Pass 2 — One idea per sentence

Long sentences are where comprehension dies. If a sentence has two ideas,
it becomes two sentences.

- **Before:** "Because loading was done by hand and every item was a
  different shape, ships spent enormous amounts of time in port, which
  meant the cost of moving goods was dominated by the loading rather than
  the voyage itself."
- **After:** "Every item was a different shape. So every item had to be
  fitted by hand. Ships spent longer parked than sailing. The expensive
  part was never the ocean — it was the edges."

Four sentences. Same content. The reader gets three places to breathe.

## Pass 3 — Concrete before abstract, always

The brain accepts a picture, then accepts the rule. Never the reverse.

- **Don't:** "Standardisation reduces transaction costs across networks."
- **Do:** "A crane in Rotterdam and a truck in Ohio can handle the same
  box without ever having spoken." *Then* name the principle.

Every abstract claim in a script should be immediately preceded by
something the viewer can see.

## Pass 4 — Numbers need a human scale

A number alone is noise. Anchor it to something the viewer owns.

- **Weak:** "Loading cost fell from $5.86 to $0.16 per ton."
- **Strong:** "Six dollars a ton, down to sixteen cents. Nobody invented a
  new engine. Somebody just agreed on a box."

Round aggressively when speaking. "About six dollars" is more
comprehensible than "$5.86" and more honest about the precision you
actually have. Keep the exact figure in the description.

## Pass 5 — Signpost the turns out loud

Viewers who drift back in need to know where they are. Say the structure.

- "To see why the box matters, you have to see what it replaced."
- "Now — this is the bit that gets left out."
- "So look at what actually changed the world here."

These cost two seconds and save the retention graph.

## Pass 6 — Read it aloud. Every word.

If you run out of breath, the sentence is too long. If you stumble, the
word order is wrong. If you're bored saying it, cut it.

This pass catches more problems than the other five combined.

---

## The comprehension checklist

Before a script goes to animation:

- [ ] Every technical term is defined in the same breath it appears
- [ ] No sentence carries two separate ideas
- [ ] Every abstract claim has a concrete image in front of it
- [ ] Every number is rounded for speech and anchored to something human
- [ ] Each section transition is announced
- [ ] The whole thing has been read aloud, start to finish
- [ ] The hook works with the sound off (the visual carries it alone)
- [ ] A smart person who knows nothing about the topic can restate the
      main point afterward — test this on an actual human
